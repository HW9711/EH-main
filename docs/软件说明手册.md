# 软件说明手册

本手册为 EH-main 工程的软件说明入口。本次建立 SSC 分支的手柄功能选择与拒绝接入说明，内容以对应提交中的源码为准。

## 产品功能配置

配置入口为 `User/Application/include/handlescan.h` 中的 `HANDLE_FUNCTION_MODE`。修改后需重新编译、烧录主控；也可通过编译选项覆盖该宏。该配置在编译时确定，不是运行中可切换的菜单设置。

| 宏值 | 名称 | 可识别范围 |
| --- | --- | --- |
| 1 | `HANDLE_FUNCTION_BOTH` | 磨削与刨削名单内的手柄 |
| 2 | `HANDLE_FUNCTION_GRINDING_ONLY` | 仅磨削名单内的手柄 |
| 3 | `HANDLE_FUNCTION_SHAVING_ONLY` | 仅刨削名单内的手柄 |

**本次提交的默认配置为 3，即仅刨削。** 0、4 等其它值会产生编译错误。任何模式都不会放行名单之外的型号，包括映射表中已有但未列入本产品功能范围的手柄。

## 手柄分类及 EEPROM 映射

型号取自通过认证的 EEPROM Page2：第一个字节为主类型，第二个字节为子类型。功能分类依据手柄型号，不依据刀具名称、旋转方向或电机类型推断。

| 功能类别 | 手柄 | Page2 主类型／子类型 | 内部型号 |
| --- | --- | --- | --- |
| 磨削 | TMBB | `0x6B / 0x01` | `TMBB_ONLINES` |
| 磨削 | TMBA | `0x6B / 0x02` | `TMBA_ONLINES` |
| 磨削 | EMBA | `0x6B / 0x03` | `EMBA_ONLINES` |
| 磨削 | EMBB | `0x6B / 0x04` | `EMBB_ONLINES` |
| 磨削 | 公共接头 | `0x6B / 0x0D` | `COMMON_SOCKET_ONLINES` |
| 磨削 | DHYTM | `0x6B / 0x10` | `DHYTM_ONLINES` |
| 刨削 | PXBA | `0x6B / 0x05` | `PXBA_ONLINES` |
| 刨削 | PXBB | `0x6B / 0x06` | `PXBB_ONLINES` |
| 刨削 | PXYTM | `0x7C / 0x03` | `PX_YIM_ONLINES` |
| 刨削 | PXYTP | `0x7C / 0x04` | `PX_YIP_ONLINES` |

PXYTP 是确认后的型号名称，PXYIP 为需求中的笔误。公共接头按磨削手柄归类；该配置限制手柄接入，接入后继续沿用原有 RFID 刀具识别规则。EEPROM 数据布局、硬件接口映射和已有型号编号未改变。

## 识别与拒绝流程

1. A/B 通道每 10ms 扫描插拔，沿用插入去抖及 EEPROM 认证流程。
2. 读取 Page2 并查找型号。认证或总线读取失败继续走既有校验、重试流程；取得有效身份后，未知型号或当前模式不允许的型号进入拒绝流程。
3. 拒绝时清除本通道识别缓存、刀具规格及 RFID 结果，不发布上线事件，不继续装载刀具和运行参数，也不开放外部导航访问。
4. 每侧分别锁存 `unsupported_latched`，复用 `HANDLESCAN_STAGE_VERIFY_FAIL` 的拔出处理。锁存期间不执行定时认证重试，不能在未拔出的情况下自动恢复上线。
5. 拔出需经过约 500ms 消抖，且离线事件成功入队后才解除本通道锁存。期间重新接通则恢复拒绝保持态；队列满时继续等待并重试离线通知。
6. 快速换柄若残留上一只手柄的在线事件配对标志，拒绝保持期间会可靠发送离线通知，撤销旧在线图标及通道记忆。

`Handlescan_HasUnsupportedHandle()` 汇总 A/B 两侧锁存状态。两侧均被拒绝时，只拔出一侧不会解除另一侧报警。

## 报警、屏幕与蜂鸣

| 项目 | 定义及行为 |
| --- | --- |
| 逻辑报警 | `WORK_ALARM_HANDLE_UNSUPPORTED = 16U` |
| 屏幕资源 | 71 号图片：“不支持该手柄” |
| 蜂鸣节奏 | 每 100ms 交替响、停，持续到最后一只被拒绝的手柄确认拔出 |
| 屏幕补刷 | 无其它系统故障优先占用时，每约 200ms 补刷 71 号提示，避免显示队列满或复位导致提示丢失 |
| 外控报告 | 沿用现有报警上报通道，报告逻辑码 16 和实际图片号 71 |

本功能不使用三声提示，也不使用限时报警。普通按键、清报警命令、泵定位及另一侧手柄恢复不能解除插入锁存。最后一只被拒绝手柄拔出后，过期的 16 号蜂鸣消息和 71 号显示消息不会重新触发该报警。

驱动等其它系统故障仍可优先显示；其解除时，若被拒绝手柄仍插着，则恢复不支持提示。拔出时若另一侧仍有手柄校验故障，则继承该侧报警，不清除其它有效故障。全局报警标志继续供既有运行门禁使用，不支持的手柄不会获得可运行身份。

## 文件与构建入口

| 文件 | 职责 |
| --- | --- |
| `User/Application/include/handlescan.h` | 三种模式宏、非法值检查、锁存查询接口 |
| `User/Application/Handle/handlescan.c` | 手柄白名单、拒绝状态、双侧归属、拔出解除及旧在线状态收尾 |
| `User/Application/include/work_alarm.h` | 16 号不支持手柄报警定义 |
| `User/Application/Common/work_alarm.c` | 清报警时保留仍有效的不支持手柄锁存 |
| `User/Application/Pubinterface/Pubinterface.c` | 将不支持手柄归入识别类报警，允许另一侧继续识别 |
| `User/Application/Beep/sscBEEP.c` | 持续蜂鸣及过期报警消息处理 |
| `User/Application/Beep/sscUIDP.c` | 71 号图片、显示补刷、关窗保护及过期消息处理 |

主要构建入口为 `EIDE/.eide/eide.yml`，EIDE 实际构建参数位于 `EIDE/build/MainCtrlF413MXOs/builder.params`，工具链为 ARM Compiler 5。本次未新增或删除 `.c` 文件，无需改变 EIDE、根构建配置或 Keil 的源文件注册关系。

## 验证范围

开发阶段已完成三种模式的 EIDE 编译、链接以及 ARM 仿真。仿真从生产源码提取相关函数，用替身模拟硬件读写、消息队列和后续参数装载流程，不代替整机硬件测试。

- 每种模式检查全部 256 个内部型号值，并覆盖 1,024 组 A/B Page2 型号输入。
- 验证名单外及未知型号拒绝上线、锁存期间不重试、导航不可访问，以及读取失败仍进入原有重试路径。
- 验证双侧拒绝、只拔一侧、拔出抖动、离线队列满、快速换柄旧在线状态收尾及另一侧校验报警继承。
- 验证按键和清报警消息不能停止持续蜂鸣，拔出后迟到的旧报警不会重新响起。
- 验证 71 号图片、周期补刷、关窗保护、其它系统故障优先显示及恢复。
- 验证宏配置 0、4 在编译阶段被拒绝。

当前尚未进行实际手柄、主控板、蜂鸣器和配套屏幕的联调。需在实机确认 71 号资源内容、插拔检测、电气时序及报警体验。
