# 软件说明手册

本手册为 EH-main 工程的软件说明入口，记录当前 R1 分支的手柄功能配置、启动检查、RFID 刀具识别、报警和构建验证。2026-10-22 以 R1 的 `e903c8c1c17a2b4420a5b706e79179d043b6c046` 为基线，合入 SSC 的 `9cd380e006fda4640adac6e804f45d8ffc053e6d` 业务修改；内容以本手册所在提交中的源码为准。

## 产品功能配置

配置入口为 `User/Application/include/handlescan.h` 中的 `HANDLE_FUNCTION_MODE`。修改后需重新编译、烧录主控；也可通过编译选项覆盖该宏。该配置在编译时确定，不是运行中可切换的菜单设置。

| 宏值 | 名称 | 可识别范围 |
| --- | --- | --- |
| 1 | `HANDLE_FUNCTION_BOTH` | 磨削与刨削名单内的手柄 |
| 2 | `HANDLE_FUNCTION_GRINDING_ONLY` | 仅磨削名单内的手柄 |
| 3 | `HANDLE_FUNCTION_SHAVING_ONLY` | 仅刨削名单内的手柄 |

**当前默认配置为 1，即同时支持磨削和刨削。** 0、4 等其它值会产生编译错误。任何模式都不会放行名单之外的型号，包括映射表中已有但未列入本产品功能范围的手柄。

## 手柄分类及 EEPROM 映射

型号取自通过认证的 EEPROM Page2：第一个字节为主类型，第二个字节为子类型。功能分类依据手柄型号，不依据刀具名称、旋转方向或电机类型推断。

| 功能类别 | 手柄 | Page2 主类型／子类型 | 内部型号 |
| --- | --- | --- | --- |
| 磨削 | TMBB | `0x6B / 0x01` | `TMBB_ONLINES` |
| 磨削 | TMBA | `0x6B / 0x02` | `TMBA_ONLINES` |
| 磨削 | EMBA | `0x6B / 0x03` | `EMBA_ONLINES` |
| 磨削 | EMBB | `0x6B / 0x04` | `EMBB_ONLINES` |
| 磨削 | 公共接头 | `0x6B / 0x0D` | `COMMON_SOCKET_ONLINES` |
| 磨削 | DHYTM | `0x6B / 0x10` | `DHYTM_ONLINES` |
| 刨削 | PXBA | `0x6B / 0x05` | `PXBA_ONLINES` |
| 刨削 | PXBB | `0x6B / 0x06` | `PXBB_ONLINES` |
| 刨削 | PXYTM | `0x7C / 0x03` | `PX_YIM_ONLINES` |
| 刨削 | PXYTP | `0x7C / 0x04` | `PX_YIP_ONLINES` |

PXYTP 是确认后的型号名称，PXYIP 为需求中的笔误。公共接头按磨削手柄归类；该配置限制手柄接入，接入后继续沿用原有 RFID 刀具识别规则。EEPROM 数据布局、硬件接口映射和已有型号编号未改变。

## 识别与拒绝流程

1. A/B 通道每 10ms 扫描插拔，沿用插入去抖及 EEPROM 认证流程。
2. 读取 Page2 并查找型号。认证或总线读取失败继续走既有校验、重试流程；取得有效身份后，未知型号或当前模式不允许的型号进入拒绝流程。
3. 拒绝时清除本通道识别缓存、刀具规格及 RFID 结果，不发布上线事件，不继续装载刀具和运行参数，也不开放外部导航访问。
4. 每侧分别锁存 `unsupported_latched`，复用 `HANDLESCAN_STAGE_VERIFY_FAIL` 的拔出处理。锁存期间不执行定时认证重试，不能在未拔出的情况下自动恢复上线。
5. 拔出需经过约 500ms 消抖，且离线事件成功入队后才解除本通道锁存。期间重新接通则恢复拒绝保持态；队列满时继续等待并重试离线通知。
6. 快速换柄若残留上一只手柄的在线事件配对标志，拒绝保持期间会可靠发送离线通知，撤销旧在线图标及通道记忆。

`Handlescan_HasUnsupportedHandle()` 汇总 A/B 两侧锁存状态。两侧均被拒绝时，只拔出一侧不会解除另一侧报警。

## 报警、屏幕与蜂鸣

| 项目 | 定义及行为 |
| --- | --- |
| 逻辑报警 | `WORK_ALARM_HANDLE_UNSUPPORTED = 16U` |
| 屏幕资源 | 71 号图片：“不支持该手柄” |
| 蜂鸣节奏 | 每 100ms 交替响、停，持续到最后一只被拒绝的手柄确认拔出 |
| 屏幕补刷 | 无其它系统故障优先占用时，每约 200ms 补刷 71 号提示，避免显示队列满或复位导致提示丢失 |
| 外控报告 | 沿用现有报警上报通道，报告逻辑码 16 和实际图片号 71 |

本功能不使用三声提示，也不使用限时报警。普通按键、清报警命令、泵定位及另一侧手柄恢复不能解除插入锁存。最后一只被拒绝手柄拔出后，过期的 16 号蜂鸣消息和 71 号显示消息不会重新触发该报警。

驱动等其它系统故障仍可优先显示；其解除时，若被拒绝手柄仍插着，则恢复不支持提示。拔出时若另一侧仍有手柄校验故障，则继承该侧报警，不清除其它有效故障。全局报警标志继续供既有运行门禁使用，不支持的手柄不会获得可运行身份。

## 每次插柄的首次缺泵检查

所有允许接入的手柄共用 `Pubinterface_CheckInjectionPumpForRun()`。A/B 分别以 `Handle_GetIdentityGeneration()` 返回的真实插拔代数记录首次状态；同型号拔出后重新插入也重新计算首次。切换方向、控制来源或接入／拔出注水泵均不重置同一次插柄的确认记录。

1. 启动前先检查手柄在线、公共接头刀具就绪、故障和控制互斥；缺泵确认不能绕过这些条件。
2. 任意一侧泵满足 `online_flag` 且 `type == INJECTWATER`，即视为已识别注水泵；吸引泵、灌注泵或离线泵不计入。首次有注水泵时正常放行，并记录本次插柄已完成首次启动检查。
3. 首次缺泵时保持手柄停止，不发出联动注水泵运行请求；蜂鸣和弹窗持续到触发来源真实释放或明确停止。持续踩住、按住、重复启动报文及报警期间接上泵都不会自动起机。
4. 对应来源释放后关闭缺泵提示，记录本次插柄已确认；第二次及后续启动不再产生缺泵蜂鸣或弹窗，也没有再次提醒后延时关闭的流程。
5. 拔出手柄会清除该通道的首次记录及当前提示。控制源失联或强制切换只撤销当前动作，不能代替真实释放完成首次确认。

| 控制来源 | 释放／确认方式 |
| --- | --- |
| 脚踏 | 有效实时数据确认真实松脚；通信超时或脚踏拔出只撤销提示，不完成确认 |
| 手控 | 本通道实体键松开或明确停止消息；数字手柄须满足有效松手帧过滤条件，另一通道松键不能代为确认 |
| 触控 | 连续约 420ms 无原始按住帧，或明确停止；原始保活先于队列过滤记录，入队失败不能伪造松手 |
| 外部控制 | 明确停手柄、全停或退出外控；重复启动不能确认，断链只撤销提示 |

| 当前运动模式 | 逻辑报警 | 屏幕图片 | 提示内容 |
| --- | --- | --- | --- |
| 正转／反转单向 | `WORK_ALARM_INJECTION_MISSING_SINGLE = 17U` | 72 | 泵管未连接，请检查，刀具未按规定连接注水，可能会损坏。 |
| 往复 | `WORK_ALARM_INJECTION_MISSING_OSC = 18U` | 73 | 泵管未连接，请检查，刀具未注水，可能影响切削性能。 |

蜂鸣任务每 100ms 读取首次缺泵状态，按响／停交替保持；显示任务按同一状态显示或关闭自己的 72／73 号图。普通按键、清音及关窗消息不能代替控制源释放；真实系统故障优先，缺泵释放不得清掉其它有效报警。外控同步逻辑码和实际图片号。泵定位失败 79 号图和压力提示 89 号图仍使用独立限时处理。

## RFID 刀具识别及启动条件

### 基座与启动检查

- 公共接头只读取 EPC，包括 MXYTM、MXYTP；EPC 连续失败也不切换 USER。启动前必须确认最新 RFID 结果已装载，识别缓存、通道记忆和运行参数的结果序号及方向掩码一致。
- PXBA／PXBB 自动识别时优先读取 EPC，仅 EPC 连续失败才读取兼容 USER。自动识别尚未取得刀具数据时，不因缺少刀具 RFID 而弹出“手柄未连接”，允许按当前参数运行；手柄在线、首次缺泵及其它故障检查继续生效。
- PXYTM／PXYTP 一体式手柄本身仍按 EEPROM 身份识别；这里的 USER 兼容格式指 PXBA／PXBB 所读的老款标签，不能把公共接头的 MXY 型号送入该兼容表。

### EPC 优先与 USER 暂存流程

1. 每次请求从 EPC 开始；快速模式最多尝试 6 次，普通模式最多 3 次。任何一次 EPC 校验正确立即发布并结束请求，不读取 USER。
2. 仅 PXBA／PXBB 在 EPC 尝试耗尽后进入 USER；USER 同样按快速最多 6 次、普通最多 3 次执行。USER 阶段若收到有效的迟到 EPC，则优先采用 EPC。
3. 读到有效 USER 后先暂存，不赋值到运行参数或界面；立即退出快速模式，按普通方式补读 EPC 最多 2 次。
4. 补读 EPC 正确则采用 EPC；两次均失败才发布暂存 USER。复核期间若发现 EPC 标识与暂存 USER 所属标签不一致，取消本次请求，避免混用两把刀的数据。
5. 一次请求只发布选定结果；后续普通轮询若取得有效 EPC，允许将此前 USER 参数升级为 EPC，此时界面仍可能再变化一次。相同标签的普通轮询保留结果序号，只更新在线读取记录。

| 配置／时间 | 当前值 | 作用 |
| --- | --- | --- |
| RFID 任务周期 | 100ms | 命令发送及接收检查的调度粒度 |
| `RFID_FAST_ATTEMPTS` | 6 | 首读 EPC、失败后 USER 各自的快速阶段预算 |
| `RFID_NORMAL_ATTEMPTS` | 3 | EPC、USER 各自的普通阶段预算 |
| `RFID_EPC_VERIFY_ATTEMPTS` | 2 | USER 暂存后普通补读 EPC 的预算 |
| 单条命令接收窗口 | 至少 100ms，分片／无效数据最多延长至 200ms | 最后一条命令也等待回包后才判失败，不能刚发出就耗尽阶段 |
| `HANDLESCAN_RFID_WAIT_TIMEOUT_MS` | 6000ms | 首次上线单轮等待，覆盖 A/B 串行读取；运行暂停不累计 |
| `HANDLESCAN_RFID_VERIFY_RETRY_MAX` | 2 | 首次 RFID 等待轮数，另有认证、排队及重试间隔 |
| `RFID_REGION_SELECT` | `RFID_REGION_CHINA_920` | 当前工作频段 920.125～924.875MHz |
| `RFID_TX_POWER_SELECT` | `RFID_TX_POWER_13_DBM_X100` | 当前发射功率 13dBm |

读取预算和射频配置集中在 `User/Application/Beep/sscRFID.c`，上线等待配置位于 `User/Application/Handle/handlescan.c`。快速与普通模式使用同一 100ms 任务周期，主要区别是尝试次数；进入 USER 后的 EPC 复核固定为普通两次。

### 帧格式和业务校验

模块回包先按 `BB` 帧头、两字节长度、累加和及末尾 `7E` 校验；数据内部出现 `7E` 不作为提前结束。下面的 `data[]` 均指提取后的业务数据，使用从 0 开始的下标。

| 来源 | 回包要求与提取位置 | 业务校验 |
| --- | --- | --- |
| EPC | `BB 02 22`，模块数据长度 17，PC 长度为 6 个字；取 `frame[8..19]` 共 12 字节 | CRC-8/SAE-J1850：初值 `FF`、多项式 `1D`、结果异或 `FF`；顺序处理除 `data[10]` 外的 11 字节，与 `data[10]` 比较 |
| USER | `BB 01 39`，模块数据长度 31，`frame[5] = 14`，PC 长度为 6 个字；从 `6 + frame[5] = 20` 开始取 16 字节 | 前 14 字节计算 MODBUS CRC16，末尾 `data[14..15]` 以高字节在前保存 |

USER 读取命令为 `BB 00 39 00 09 00 00 00 00 03 00 00 00 08 4D 7E`。

| USER 字段 | 解析及限制 |
| --- | --- |
| `data[4]` | `01` 对应 PXYTP，`02` 对应 PXYTM；其它型号拒绝 |
| `data[5]` 高半字节 | PXYTP 要求 3 个方向，PXYTM 要求 1 个方向 |
| `data[8]` | 最大速度，乘 500 得到 rpm |
| `data[9]` | 默认速度，乘 500 得到 rpm |
| `data[10]` | 频率指令；PXYTP 保留 5～40 范围检查 |
| `data[11]` | 默认注水流量 |

PXYTM／PXYTP 的 USER 不再使用固定速度、非零速度、默认速度与最小／最大速度关系或减速后速度上限作为识别条件。EPC 仍保留自身的方向、倍率、速度范围和驱动字段上限检查，两种来源的规则不混用。例如 USER `26 28 1A 46 02 11 00 05 1A 14 00 14 00 00 C6 38` 解析为最大 13000rpm、默认 10000rpm。

EPC 的 `data[0]` 包含格式标记、型号、方向数量和默认方向；`data[4..5]` 保存倍率，`data[6]`／`data[7]`／`data[8]` 分别为最大／最小／默认速度，单位 1000rpm。

| EPC 型号 | 方向规则 |
| --- | --- |
| MXYTP，`0x04` | 要求仅一种方向且默认往复；界面固定显示往复，驱动输出始终正转，由机械结构形成往复 |
| MXYTM，`0x05` | 接受默认正转、反转及声明正反两方向的合法标签，不再因方向数量为 2 拒绝；仍禁止电气往复，当前界面方向保持标签默认值，实际电机方向与其一致 |

SSC 分支历史验证记录已覆盖 EPC `67 80 69 15 00 0A 3C 0A 3C 20 13 20` 和 `AD 10 20 30 F0 14 78 0A 78 1E 7E 32`；两者业务 CRC 分别为 `13` 和 `7E`。

## 泵流量、脚踏快捷档与重连

左右泵按插口固定业务类型：A／左侧为注水泵，压力数据来自 `SIM_UART_1/PE4`；B／右侧为灌注泵，压力数据来自 `SIM_UART_2/PE6`。以下流量单位均为 mL/min。

| 泵侧及模式 | 本次主机开机首次有效识别的默认流量 | 对应脚踏短按快捷档 |
| --- | --- | --- |
| A／左侧注水 | 30 | 20 → 25 → 30 → 20 |
| B／右侧灌注 | 120 | 90 → 120 → 180 → 90 |

- 灌注快捷档仅由右脚踏短按调节右侧 B 泵，使用非等距档位表；左侧注水快捷流量仍为 20／25／30。刚识别后的第一次短按进入首档，后续依次循环；快捷切档只调整流量，不改变启停请求。
- A/B 各自记录本次开机是否完成首次有效识别。此前未接入或无效设备码不会占用首次初始化；第一次有效接入分别设为 30／120，普通上报帧不覆盖后续设定。
- 设备码报告离线或压力通信超时后，再次识别同侧模块均保留最近设定流量，包括 0 和非快捷档数值。掉线清除运行请求及排空请求；重连本身不恢复运行，需重新发起启动动作。
- 上下线仍将脚踏档位索引清零，但不改写已经初始化的流量；重连后第一次短按将进入对应首档。流量记忆仅在本次主机开机期间有效，主机重新上电后首次接入重新使用默认值。
- 保留 0 设定只描述重连行为；随后启动仍沿用已有零流量补速逻辑：注水按当前通道 Page4 默认流量、非法值回退 30，灌注补为 120。

`User/Application/include/pump.h` 中的 `PUMP_POURWATER_DEFAULT_FLOW` 为 120，同时供首次识别和零流量启动补速使用。`User/Application/Pump/pump_control.c` 的 `Pump_HandleGearKey()` 定义快捷档；`User/Peripheral/uart/soft_uart.c` 的 `s_cs1237_flow_initialized` 和 `Cs1237_UpdatePumpMessage()` 保证每侧仅初始化一次。
