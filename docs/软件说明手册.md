# 软件说明手册

本手册为 EH-main 工程的软件说明入口，记录当前 R1 分支的手柄功能配置、启动检查、RFID 刀具识别、报警和构建验证。2026-10-22 以 R1 的 `e903c8c1c17a2b4420a5b706e79179d043b6c046` 为基线，合入 SSC 的 `9cd380e006fda4640adac6e804f45d8ffc053e6d` 业务修改；内容以本手册所在提交中的源码为准。当前业务说明已同步至2026-10-29，包含停机发送确认与重启联锁、GZYT临时支持、屏幕B有刷电流校准、USER兼容参数，以及UART2简易外控调速和泵流量循环。

## 产品功能配置

配置入口为 `User/Application/include/handlescan.h` 中的 `HANDLE_FUNCTION_MODE`。修改后需重新编译、烧录主控；也可通过编译选项覆盖该宏。该配置在编译时确定，不是运行中可切换的菜单设置。

| 宏值 | 名称 | 可识别范围 |
| --- | --- | --- |
| 1 | `HANDLE_FUNCTION_BOTH` | 磨削与刨削名单内的手柄 |
| 2 | `HANDLE_FUNCTION_GRINDING_ONLY` | 仅磨削名单内的手柄 |
| 3 | `HANDLE_FUNCTION_SHAVING_ONLY` | 仅刨削名单内的手柄 |

**当前默认配置为 1，即同时支持磨削和刨削。** 0、4 等其它值会产生编译错误。正式产品模式不放行名单之外的型号；临时测试例外为 `GZYT_DIGITAL_TEST_ENABLE = 1U` 时允许GZYT在A/B通道上线，独立于上述三种模式。该宏位于 `User/Application/include/handlekey.h`，设为0恢复GZYT拒绝上线并关闭数字按钮测试；EEPROM认证和其余启动门禁仍须通过。

## 手柄分类及 EEPROM 映射

型号取自通过认证的 EEPROM Page2：第一个字节为主类型，第二个字节为子类型。功能分类依据手柄型号，不依据刀具名称、旋转方向或电机类型推断。

| 功能类别 | 手柄 | Page2 主类型／子类型 | 内部型号 |
| --- | --- | --- | --- |
| 磨削 | TMBB | `0x6B / 0x01` | `TMBB_ONLINES` |
| 磨削 | TMBA | `0x6B / 0x02` | `TMBA_ONLINES` |
| 磨削 | EMBA | `0x6B / 0x03` | `EMBA_ONLINES` |
| 磨削 | EMBB | `0x6B / 0x04` | `EMBB_ONLINES` |
| 磨削 | 公共接头 | `0x6B / 0x0D` | `COMMON_SOCKET_ONLINES` |
| 磨削 | DHYTM | `0x6B / 0x10` | `DHYTM_ONLINES` |
| 刨削 | PXBA | `0x6B / 0x05` | `PXBA_ONLINES` |
| 刨削 | PXBB | `0x6B / 0x06` | `PXBB_ONLINES` |
| 刨削 | PXYTM | `0x7C / 0x03` | `PX_YIM_ONLINES` |
| 刨削 | PXYTP | `0x7C / 0x04` | `PX_YIP_ONLINES` |
| 临时测试 | GZYT | `0x6B / 0x11` | `GZYT_ONLINES` |

PXYTP 是确认后的型号名称，PXYIP 为需求中的笔误。公共接头按磨削手柄归类；该配置限制手柄接入，接入后继续沿用原有 RFID 刀具识别规则。EEPROM 数据布局、硬件接口映射和已有型号编号未改变。

## 识别与拒绝流程

1. A/B 通道每 10ms 扫描插拔，沿用插入去抖及 EEPROM 认证流程。
2. 读取 Page2 并查找型号。认证或总线读取失败继续走既有校验、重试流程；取得有效身份后，未知型号或当前模式不允许的型号进入拒绝流程。
3. 拒绝时清除本通道识别缓存、刀具规格及 RFID 结果，不发布上线事件，不继续装载刀具和运行参数，也不开放外部导航访问。
4. 每侧分别锁存 `unsupported_latched`，复用 `HANDLESCAN_STAGE_VERIFY_FAIL` 的拔出处理。锁存期间不执行定时认证重试，不能在未拔出的情况下自动恢复上线。
5. 拔出需经过约 500ms 消抖，且离线事件成功入队后才解除本通道锁存。期间重新接通则恢复拒绝保持态；队列满时继续等待并重试离线通知。
6. 快速换柄若残留上一只手柄的在线事件配对标志，拒绝保持期间会可靠发送离线通知，撤销旧在线图标及通道记忆。

`Handlescan_HasUnsupportedHandle()` 汇总 A/B 两侧锁存状态。两侧均被拒绝时，只拔出一侧不会解除另一侧报警。

## 报警、屏幕与蜂鸣

| 项目 | 定义及行为 |
| --- | --- |
| 逻辑报警 | `WORK_ALARM_HANDLE_UNSUPPORTED = 16U` |
| 屏幕资源 | 71 号图片：“不支持该手柄” |
| 蜂鸣节奏 | 每 100ms 交替响、停，持续到最后一只被拒绝的手柄确认拔出 |
| 屏幕补刷 | 无其它系统故障优先占用时，每约 200ms 补刷 71 号提示，避免显示队列满或复位导致提示丢失 |
| 外控报告 | 沿用现有报警上报通道，报告逻辑码 16 和实际图片号 71 |

本功能不使用三声提示，也不使用限时报警。普通按键、清报警命令、泵定位及另一侧手柄恢复不能解除插入锁存。最后一只被拒绝手柄拔出后，过期的 16 号蜂鸣消息和 71 号显示消息不会重新触发该报警。

驱动等其它系统故障仍可优先显示；其解除时，若被拒绝手柄仍插着，则恢复不支持提示。拔出时若另一侧仍有手柄校验故障，则继承该侧报警，不清除其它有效故障。全局报警标志继续供既有运行门禁使用，不支持的手柄不会获得可运行身份。

手柄EEPROM认证恢复并装载基座参数后立即解除该通道旧校验报警，无刀具RFID不再延长EEPROM校验异常。显示任务通过 `Handlescan_GetVerifyAlarmForDisplay()` 查询实际报警来源，维护90号图的显示和关闭；队列丢消息或写屏失败时按 `UIDP_VERIFY_ALARM_RETRY_MS = 100ms` 重试。只有整帧发送成功才更新显示归属和外控屏幕报警报告，此结果不等于屏幕回读确认。另一侧仍校验失败时保留其提示，不关闭其它真实故障。

## 电机停机发送与重新启动

主控每50ms按当前运行状态发送电机帧。STOP沿用最近RUN的通道、方向、模式和电流字段，仅清零速度并重新计算CRC；首次尚无RUN模板时使用兼容零速帧。只有UART1返回HAL_OK才更新命令快照并清除STOP待发送状态，该结果表示主控发送成功，不等于驱动应答或电机机械停稳。

STOP或启动前零速帧发送失败时，撤销手柄运行请求并建立原驱动通信故障Err=13，后续周期继续补发STOP；不以旧RUN快照跳过零速重装。首次启动、停止后启动或STOP待补发时，先发同配置零速，再保留5ms间隔；间隔结束重新检查运行请求、全局报警及脚踏停止锁存，期间松脚或报警则发送STOP，不发送此前组装的RUN。运行中正常调速不额外插入零速。

驱动反馈Err=16（停机超时）或17（停机参数无效）映射逻辑报警11（驱动板故障），图片值255表示无专用图片，保留停机和蜂鸣，不显示刀具过载。这些驱动原始Err与逻辑报警16“不支持该手柄”属于不同编号域。驱动内部停机期限及关断实现位于独立驱动工程，不包含在本主控提交中。

## 屏幕B有刷电流校准

配置入口为 `User/Application/Beep/sscDrive.c` 的 `MOTOR_DRIVE_SCREEN_B_BRUSHED_CURRENT_DIVISOR_X100`，当前114U表示除以1.14，110U表示除以1.10，100U表示不校准。仅屏幕B且最终电机类型为0x03或0x04时生效；当前A/B互换配置下，屏幕B有刷对应物理A的0x03。屏幕A和无刷类型保持原值。

每次组帧从原始 `WorkMessage.current_work` 重新取值，以32位整数计算并四舍五入到0.01A后发送，零值仍为零。EEPROM、通道记忆和原始保护设定不被回写，重复发送不会累计缩小；RUN和后续STOP模板使用同一校准阈值。

## 开机准备等待与输入联锁

开机前置显示及脚踏定标时序保持原样；业务任务运行后，由显示任务等待外设准备，不能通过延长任务启动前的阻塞延时替代。显示任务首周期预写控件并保留当前真实故障，此时仍显示启动页。原 `UI_POWERINIT_ID` 消息不再直接切页，初始化消息丢失或迟到也不能跳过等待或重置运行页参数。

| 显示阶段 | 行为与转移条件 |
| --- | --- |
| 0：未预写 | 默认即禁止运行请求；显示任务首周期直接预写控件，记录起始时刻并进入阶段1。 |
| 1：等待准备 | 至少经过2秒首帧观察窗口，且手柄、已识别泵及有效脚踏均不再处于准备中，才排入当前手柄和A/B泵显示快照并进入阶段2。 |
| 2：等待显示队列 | 继续处理正常显示消息，队列清空后切到主运行页page4；期间若任一设备重新处于准备中，回到阶段1并在完成后重新获取快照。 |
| 3：主运行页开放 | 允许新的控制请求，保留原3秒状态补刷；不会因迟到的初始化消息再次切页。 |

已接入设备按以下规则汇总，不要求所有接口接满：

- 手柄按A/B物理插口分别检查。首次认证、参数读取或首读RFID尚未收尾时继续等待；扫描进入ONLINE后还须等上线消息装入通道记忆。明确进入VERIFY_FAIL时允许展示故障；空接口或已拔出接口不阻塞。空基座的首读事务结束后可以上线，不要求一直等到识别到刀具RFID。
- 泵只检查机型启用、已经识别在线且类型有效的通道。任一路仍在首次定位、首次失败后的2秒自动重试等待或已登记定位流程中，都保持启动页；一路失败不能掩盖另一路仍在准备。两侧准备均结束后，按新鲜反馈及原驱动门禁判定就绪或失败；原30秒定位超时、取消及反馈保护继续生效，切页不解除失败泵的运行限制。
- 脚踏已收到有效实时帧但定标或上线消息尚未完成时继续等待。没有有效实时帧的空接口、已上线脚踏或明确定标错误不阻塞切页，原运行门禁和故障提示继续生效。

切页时优先显示当前真实系统故障；没有全局故障但存在未就绪泵时，重新显示79号图约3秒，避免提示在启动页期间已经到期。这次补显不另加蜂鸣，定位结果蜂鸣仍由原泵流程处理。泵失败后的手动重试与成功后重新启动规则见“泵定位失败后的手动重试”。

`UIDP_IsStartupWaiting()` 在阶段0～2返回等待。`SendKeyBehMessage()` 此时只保留插拔消息，拒绝操作按键入队；`ControlArbitration_TryEnter()` 同时拒绝脚控、手控、触控和外控取得运行控制权，准备期间的操作不会排队到切页后补执行。后台识别、通信、显示及看门狗任务继续调度。

脚踏任务在等待期间仍处理连接消息，但不执行轻踩泵、深踩电机或通道切换，并持续要求重新松脚。进入主运行页后，单踏板、双段踏板或双脚踏须连续3个25ms周期确认完全释放；双脚踏要求左右同时释放。确认完成的当周期仍不执行踏板动作，下一周期才恢复原处理。开机一直踩住不会因切页自动起机；无效实时帧会打断连续松脚确认。

| 配置／查询入口 | 含义 |
| --- | --- |
| `UIDP_STARTUP_DISCOVERY_MS`，`sscUIDP.c` | 2000ms，从显示任务首次预写开始计时；只是最小观察窗口，不是强制切页时间，也不是整机开机总时长。 |
| `UIDP_IsStartupWaiting()` | 主运行页尚未开放时返回1，作为操作入队及控制权入口的统一联锁。 |
| `Handlescan_IsStartupPending()` | 已插入手柄仍在认证、首读或上线交接时返回true。 |
| `PumpBehavior_GetStartupState()` | 0：全部就绪或未接入；1：仍在准备；2：准备结束但至少一路未就绪。 |
| `Foot_IsStartupPending()` | 已有有效脚踏实时帧但定标或上线未完成时返回1；明确错误不无限等待。 |

## 每次插柄的首次缺泵检查

所有允许接入的手柄共用 `Pubinterface_CheckInjectionPumpForRun()`。A/B 分别以 `Handle_GetIdentityGeneration()` 返回的真实插拔代数记录首次状态；同型号拔出后重新插入也重新计算首次。切换方向、控制来源或接入／拔出注水泵均不重置同一次插柄的确认记录。

1. 主运行页开放后，启动前先检查手柄在线、故障和控制互斥；公共接头不再按RFID是否识别单独拦截，缺泵确认不能绕过其余条件。
2. 任意一侧泵满足 `online_flag` 且 `type == INJECTWATER`，即视为已识别注水泵；吸引泵、灌注泵或离线泵不计入。首次有注水泵时正常放行，并记录本次插柄已完成首次启动检查。
3. 首次缺泵时保持手柄停止，不发出联动注水泵运行请求；蜂鸣和弹窗持续到触发来源真实释放或明确停止。持续踩住、按住、重复启动报文及报警期间接上泵都不会自动起机。
4. 对应来源释放后关闭缺泵提示，记录本次插柄已确认；第二次及后续启动不再产生缺泵蜂鸣或弹窗，也没有再次提醒后延时关闭的流程。
5. 拔出手柄会清除该通道的首次记录及当前提示。控制源失联或强制切换只撤销当前动作，不能代替真实释放完成首次确认。

| 控制来源 | 释放／确认方式 |
| --- | --- |
| 脚踏 | 有效实时数据确认真实松脚；通信超时或脚踏拔出只撤销提示，不完成确认 |
| 手控 | 本通道实体键松开或明确停止消息；数字手柄须满足有效松手帧过滤条件，另一通道松键不能代为确认 |
| 触控 | 连续约 420ms 无原始按住帧，或明确停止；原始保活先于队列过滤记录，入队失败不能伪造松手 |
| 外部控制 | 明确停手柄、全停或退出外控；重复启动不能确认，断链只撤销提示 |

| 当前运动模式 | 逻辑报警 | 屏幕图片 | 提示内容 |
| --- | --- | --- | --- |
| 正转／反转单向 | `WORK_ALARM_INJECTION_MISSING_SINGLE = 17U` | 72 | 泵管未连接，请检查，刀具未按规定连接注水，可能会损坏。 |
| 往复 | `WORK_ALARM_INJECTION_MISSING_OSC = 18U` | 73 | 泵管未连接，请检查，刀具未注水，可能影响切削性能。 |

蜂鸣任务每 100ms 读取首次缺泵状态，按响／停交替保持；显示任务按同一状态显示或关闭自己的 72／73 号图。普通按键、清音及关窗消息不能代替控制源释放；真实系统故障优先，缺泵释放不得清掉其它有效报警。外控同步逻辑码和实际图片号。泵定位失败 79 号图和压力提示 89 号图仍使用独立限时处理。

## RFID 刀具识别及启动条件

### 基座与启动检查

- 公共接头只读取 EPC，包括 MXYTM、MXYTP；EPC 连续失败也不切换 USER。与PX一样按当前参数处理启动，未识别RFID或射频掉线不再单独触发“手柄未连接”报警或启动拦截。手柄物理在线、方向许可、非零速度、首次缺泵、控制互斥、脚踏松开及驱动故障检查继续生效。
- PXBA／PXBB 自动识别时优先读取 EPC，仅 EPC 连续失败才读取兼容 USER。自动识别尚未取得刀具数据时，不因缺少刀具 RFID 而弹出“手柄未连接”，允许按当前参数运行；手柄在线、首次缺泵及其它故障检查继续生效。
- PXYTM／PXYTP 一体式手柄本身仍按 EEPROM 身份识别；这里的 USER 兼容格式指 PXBA／PXBB 所读的老款标签，不能把公共接头的 MXY 型号送入该兼容表。

### EPC 刀具调速步进

公共接头和分体式 PXBA／PXBB 的新 EPC 刀具，在最大转速大于最小转速时，按刀具转速差统一设置正转、反转、往复的小／大步进：差值不超过10000rpm时为500／1000rpm；大于10000rpm且小于70000rpm时为1000／5000rpm；达到70000rpm时为2000／10000rpm。最大转速等于或低于最小转速时不进入范围分档，保留基础步进并沿用后续零值兜底。老 USER 标签仍按型号兼容表设置步进；手动模式不进入该 RFID 装载分支，方向许可和独立往复频率规则不变。

### EPC 优先与 USER 暂存流程

1. 每次请求从 EPC 开始；快速模式最多尝试 6 次，普通模式最多 3 次。任何一次 EPC 校验正确立即发布并结束请求，不读取 USER。
2. 仅 PXBA／PXBB 在 EPC 尝试耗尽后进入 USER；USER 同样按快速最多 6 次、普通最多 3 次执行。USER 阶段若收到有效的迟到 EPC，则优先采用 EPC。
3. 读到有效 USER 后先暂存，不赋值到运行参数或界面；立即退出快速模式，按普通方式补读 EPC 最多 2 次。
4. 补读 EPC 正确则采用 EPC；两次均失败才发布暂存 USER。复核期间若发现 EPC 标识与暂存 USER 所属标签不一致，取消本次请求，避免混用两把刀的数据。
5. 一次请求只发布选定结果；后续普通轮询若取得有效 EPC，允许将此前 USER 参数升级为 EPC，此时界面仍可能再变化一次。相同标签的普通轮询保留结果序号，只更新在线读取记录。

### 首读交接、参数锁存与蜂鸣

基座EEPROM认证成功后先上线基座；首次RFID读取使用请求票据追踪实际完成状态。首读成功即装载刀具；已完成但没有有效刀具时立即进入在线监测，不再固定等待6秒、重读EEPROM后进行第二轮首读。只有事务仍未完成时使用6秒兜底；运行中仍暂停RFID读取及新结果装载。

公共接头与PXBA／PXBB在射频掉线时锁存最后有效刀具信息、规格及当前参数。公共接头同一完整RFID信息恢复后，保留用户调节的正转／反转／往复转速、频率和合法方向；A/B分别记忆。匹配依据包括读取来源、数据长度及完整数据内容，不只比较刀具型号；不同有效RFID信息才装载新的默认参数，方向仍受标签规则限制。

掉线和相同RFID恢复保持静默，首次或不同有效刀具信息装载后单响一次，真实基座插拔提示保留。真实拔柄仍清除该通道记忆，主机重启也不保留这份RAM参数；本功能不写EEPROM。无历史有效刀具的空公共接头不会凭空补出非零转速，零速度仍发送停止命令。保留的 `Handlescan_IsRfidToolReady()` 仅供外控数据有效性判断，不能把历史锁存参数当作当前有效RFID上报；诊断字段 `missing_tool_release` 保留原位置并固定为0。

### 帧格式和业务校验

模块回包先按 `BB` 帧头、两字节长度、累加和及末尾 `7E` 校验；数据内部出现 `7E` 不作为提前结束。下面的 `data[]` 均指提取后的业务数据，使用从 0 开始的下标。

| 来源 | 回包要求与提取位置 | 业务校验 |
| --- | --- | --- |
| EPC | `BB 02 22`，模块数据长度 17，PC 长度为 6 个字；取 `frame[8..19]` 共 12 字节 | CRC-8/SAE-J1850：初值 `FF`、多项式 `1D`、结果异或 `FF`；顺序处理除 `data[10]` 外的 11 字节，与 `data[10]` 比较 |
| USER | `BB 01 39`，模块数据长度 31，`frame[5] = 14`，PC 长度为 6 个字；从 `6 + frame[5] = 20` 开始取 16 字节 | 前 14 字节计算 MODBUS CRC16，末尾 `data[14..15]` 以高字节在前保存 |

USER 读取命令为 `BB 00 39 00 09 00 00 00 00 03 00 00 00 08 4D 7E`。

| USER 字段 | 解析及限制 |
| --- | --- |
| `data[4]` | `01` 对应 PXYTP，`02` 对应 PXYTM；其它型号拒绝 |
| `data[5]` 高半字节 | PXYTP 要求 3 个方向，PXYTM 要求 1 个方向 |
| `data[8]` | 最大速度，乘 500 得到 rpm |
| `data[9]` | 默认速度，乘 500 得到 rpm |
| `data[10]` | 频率指令；PXYTP 保留 5～40 范围检查 |
| `data[11]` | 默认注水流量 |

PXBA／PXBB自动模式读取上述兼容USER时，当前代码表中USER型号01（PXYTP）的倍率为5.00、保护电流200（2.00A）；USER型号02（PXYTM）的倍率为1.90、保护电流400（4.00A）。速度仍取USER字段。这是老款标签的兼容参数，不代表PXYTM／PXYTP一体式EEPROM参数，也不是PXBA／PXBB手动模式的新三档阈值；本提交尚未修改EEPROM布局或手动模式电流规则。

PXYTM／PXYTP 的 USER 不再使用固定速度、非零速度、默认速度与最小／最大速度关系或减速后速度上限作为识别条件。EPC 仍保留自身的方向、倍率、速度范围和驱动字段上限检查，两种来源的规则不混用。例如 USER `26 28 1A 46 02 11 00 05 1A 14 00 14 00 00 C6 38` 解析为最大 13000rpm、默认 10000rpm。

EPC 的 `data[0]` 包含格式标记、型号、方向数量和默认方向；`data[4..5]` 保存倍率，`data[6]`／`data[7]`／`data[8]` 分别为最大／最小／默认速度，单位 1000rpm。

| EPC 型号 | 方向规则 |
| --- | --- |
| MXYTP，`0x04` | 要求仅一种方向且默认往复；界面固定显示往复，驱动输出始终正转，由机械结构形成往复 |
| MXYTM，`0x05` | 接受默认正转、反转及声明正反两方向的合法标签，不再因方向数量为 2 拒绝；仍禁止电气往复，当前界面方向保持标签默认值，实际电机方向与其一致 |

SSC 分支历史验证记录已覆盖 EPC `67 80 69 15 00 0A 3C 0A 3C 20 13 20` 和 `AD 10 20 30 F0 14 78 0A 78 1E 7E 32`；两者业务 CRC 分别为 `13` 和 `7E`。

## UART2简易外控调节

固定帧为 `AA BB CC FunCode EE FF`，沿用既有外控授权和协议入口。功能码05／06按屏幕减速／加速规则处理当前手柄，复用屏幕可用性检查、当前方向上下限和小步进；有效操作给100ms单响，禁止操作不改参数也不响。

功能码0A／0B分别调节A／B泵：未达上限时按屏幕加流量步进递增并限幅，本次刚到上限仍保留上限；已在上限时的下一次操作回到该泵配置下限。流程检查屏幕门禁和泵类型，清除旧脚踏档位进度并刷新对应泵，有效操作给一次按键音。两路分别循环，不使用脚踏预设档，不修改启停请求。

## 泵流量、脚踏快捷档与重连

左右泵按插口固定业务类型：A／左侧为注水泵，压力数据来自 `SIM_UART_1/PE4`；B／右侧为灌注泵，压力数据来自 `SIM_UART_2/PE6`。以下流量单位均为 mL/min。

| 泵侧及模式 | 本次主机开机首次有效识别的默认流量 | 对应脚踏短按快捷档 |
| --- | --- | --- |
| A／左侧注水 | 30 | 20 → 25 → 30 → 20 |
| B／右侧灌注 | 120 | 90 → 120 → 180 → 90 |

- 灌注快捷档仅由右脚踏短按调节右侧 B 泵，使用非等距档位表；左侧注水快捷流量仍为 20／25／30。刚识别后的第一次短按进入首档，后续依次循环；快捷切档只调整流量，不改变启停请求。
- A/B 各自记录本次开机是否完成首次有效识别。此前未接入或无效设备码不会占用首次初始化；第一次有效接入分别设为 30／120，普通上报帧不覆盖后续设定。
- 设备码报告离线或压力通信超时后，再次识别同侧模块均保留最近设定流量，包括 0 和非快捷档数值。掉线清除运行请求及排空请求；重连本身不恢复运行，需重新发起启动动作。
- 上下线仍将脚踏档位索引清零，但不改写已经初始化的流量；重连后第一次短按将进入对应首档。流量记忆仅在本次主机开机期间有效，主机重新上电后首次接入重新使用默认值。
- 保留0设定只描述重连行为。当前 `Pump_HandleRunKey()` 的A泵普通启动补速语句已注释，0设定不会自动补为非零；B泵普通启动及注水轻排仍调用补速函数，注水按Page4默认流量、非法值回退30，灌注补为120。屏幕注水定时排空的输出另由泵任务处理，不能把运行标志等同于实际流量。

`User/Application/include/pump.h` 中的 `PUMP_POURWATER_DEFAULT_FLOW` 为 120，同时供首次识别和零流量启动补速使用。`User/Application/Pump/pump_control.c` 的 `Pump_HandleGearKey()` 定义快捷档；`User/Peripheral/uart/soft_uart.c` 的 `s_cs1237_flow_initialized` 和 `Cs1237_UpdatePumpMessage()` 保证每侧仅初始化一次。

## 灌注压力调流与检测提示

A/B泵任务周期均为25ms。压力总开关 `PUMP_PRESSURE_CONTROL_ENABLE` 和灌注开关 `PUMP_PRESSURE_POUR_PROTECTION_ENABLE` 当前均为1。灌注按当前下发流量选阈值，不按用户原设定选档；主控直接比较0.1g整数，mmHg目标由 `P90-MEDIAN-PIECEWISE-20261021-V1` 离线换算，中间流量对g阈值插值，启动向上取整、恢复向下取整。

| --- | --- | --- |
| ≤100 | 100／50 | 256.7／32.6 |
| 120 | 110／60 | 305.7／57.9 |

1. 正常状态连续达到启动线500ms后开始降流。当前输出≥200时先降至160；100～199每档减20，低于100每档减10，一级下限为20或用户更低设定。每档至少等待500ms且收到新压力，不使用重复旧帧连续调档。
2. 已确认的本轮堵塞尚未解除时，即使压力回落到启动线与恢复线之间，一级仍逐档下降；落到恢复线及以下先观察，连续稳定1秒才解除堵塞记录并允许逐步恢复。
3. 到20或用户更低设定后再观察500ms，压力仍高于恢复线且堵塞记录未解除时进入不高于5的低流量。进入该状态即提示本轮一次：三声蜂鸣、89号图3秒；不再以累计高压5秒或300mmHg提前提示作为升级条件。
4. 低流量阶段压力≤本档恢复线连续1秒后，每次增加20，且每一档重新确认1秒，最高不超过当前用户设定。恢复过程中压力持续高于本档恢复线500ms即退回不高于5，再等下一段稳定低压；没有永久锁定和恢复次数限制。25档采用50mmHg对应的恢复线。

## 泵定位失败后的手动重试

泵驱动反馈高4位 `0x80` 为就绪、`0x90` 为定位中、`0xA0` 为定位失败；还须检查低4位故障和100ms反馈有效期。上电首次明确定位失败后等待2秒，仅自动重试一次；定位流程等待上限30秒。未装配或未识别在线的通道不阻塞启动页；已识别泵的定位或自动重试未结束时继续等待，准备完成或明确失败后才允许切页。A/B装配开关沿用 `PUMP_CHANNEL_A_ENABLE`／`PUMP_CHANNEL_B_ENABLE`，当前双泵配置。

自动重试失败报警后，不再要求断电。对应屏幕泵启动键可申请新一轮定位：泵必须在线、有有效失败反馈且无运行、排空、全局报警或待处理取消请求，手柄也必须停止。每次申请先发两帧普通零速，再发一次 `0x02` 零速定位命令；申请后500ms未进入定位的等待沿用应答限制。手动重试重新建立30秒等待上限，每次仅执行一次，不追加自动重试。

**每次手动定位再次失败，均重新显示79号定位失败图约3秒并蜂鸣两声；同一次失败的重复回包不会反复提示。失败后保持停泵，仍可再次按对应屏幕键重试。** 定位成功只解除停止限制，必须再按一次启动键才正常开泵；脚踏或HMI重复启动不会发起重新定位。全停取消使用 `0x03` 零速命令并优先处理，原故障、反馈超时和停止保护继续生效。普通按键音不受未接入泵的定位等待影响。

## 方向权限、手动保护电流与往复输出

新版手柄EEPROM Page4[23]以十六进制00表示旧版、01表示仅默认方向、10表示正反转、11表示正反往复；Page4[8]给出默认方向。新版方向与有效RFID许可取交集，非法扩展或禁止方向在最终驱动发送入口转为停止；旧版保留原型号限制。RFID换刀保留本体配置，真实拔柄清除当前配置，A/B通道独立保存。DHYTM旧版仍固定电机正转；新版正反转按反旋机械关系互换，往复保持。

分体手柄切换手动模式时，重新读取本通道 EEPROM 通用保护电流，并同时更新通道记忆和当前工作态，避免旧版手柄沿用上一把 RFID 刀具的电流阈值。新版手动模式仍按以下三档规则选择保护电流。

PXBA/PXBB新版手动模式：Page4[24..25]为磨头低速保护电流，[26..27]为磨头高速保护电流，[28..29]为刨刀保护电流，均为LE16、单位0.01A。磨头以屏幕设定转速30000rpm分档，等于阈值取高速档；刨刀独立取值。无效零电流禁止运行，之后才执行屏幕B有刷电流校准，不回写原参数。PXBA/PXBB实际电气往复的非零目标最低按刀具端700rpm输出，然后换算减速比；零速仍停止。

心跳A7运行扩展为版本03、共13字节；保留原字段，相对A7偏移9/10为A可选方向位图/设置方向，11/12为B对应字段。位图01正转、02反转、04往复；设置方向01/02/03，离线为00/FF。

## 软件版本查询与独立页保存

主控版本入口为 User/Peripheral/include/mainboard_software_version.h 的 MAINBOARD_SW_VERSION_BASE_TEXT；手柄和泵驱动分别在其 UserCode/driver_software_version.h、USER/driver_software_version.h 设置 DRIVER_SW_BASE_VERSION，版本最多8个ASCII字符。固件标记为MBSWVER1、MTSWVER1、PPSWVER1；版本为人工字符串加CRC32，范围0x08000000起256KB，手柄参数区0x08031800至0x080347FF按FF归一化。驱动仅上电或复位初始化计算，普通启停和版本查询使用缓存。

| 主控AT24C32用途 | 页 | 地址 |
| --- | --- | --- |
| 主控版本 | Page1 | 0x0000 |
| 手柄驱动版本 | Page2 | 0x0020 |
| A泵版本 | Page3 | 0x0040 |
| B泵版本 | Page4 | 0x0060 |

每页32字节，SWV1标记、格式1、版本文本8字节、CRC算法1、起始地址/长度/CRC32按大端保存；byte26板类型0主控/1手柄/2泵，byte27参数归一化规则0普通/1手柄，byte30~31为前30字节累加和。只在变化时写入并读回核对。这是主控板EEPROM，区别于手柄业务EEPROM同名页。

外控功能码0B无请求数据，AreaCode为FF主控、01手柄、02A泵、03B泵；响应固定状态1字节加记录32字节。状态0有效，1参数错误，2读失败，3写入或读回失败，4页和错误，5标记错误，6格式或板型不符，7忙，8超时，9响应不支持，10运行中拒绝或取消。失败不得把历史EEPROM记录当作当前版本。

上电5秒后停止状态依次尝试同步三块驱动一次；手动读取重新查询。手柄复用UART1的FD/03、7E00起16寄存器维护请求；泵使用独立AB查询及37字节CRC响应。泵仅在停止、零速反馈有效且未定位时替换一次停止帧，后续恢复25ms控制周期；版本响应不会进入速度/故障解析。新运行请求取消维护并释放UART，版本写回只在停止状态进行。

实现索引：mainboard_software_version.c/.h负责查询与持久化，external_comm_task.c负责外控和启动同步，pump_behavior_core.c负责安全周期查询及响应分流；handlescan.c、handle_control.c、Pubinterface.c/.h、sscDrive.c负责方向、配置和输出门禁。本次没有新增C编译单元。
