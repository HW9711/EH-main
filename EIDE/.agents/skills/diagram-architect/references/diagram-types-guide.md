## 概述

本文档提供图表类型判断的标准和方法，帮助智能体根据用户描述的内容特征，选择最合适的可视化形式。

**核心原则：**
- 图表类型服务于内容结构
- 同一内容可能有多种适合的图表类型
- 优先选择最能清晰表达核心关系的类型

---

## 图表类型分类

### 按结构特征分类

| 结构特征 | 适合图表 | 典型场景 |
|---------|---------|---------|
| 线性流程 | 流程图、时序图 | 业务流程、操作步骤 |
| 层级关系 | 组织架构图、树图 | 组织结构、分类体系 |
| 网状关系 | 系统架构图、关系图 | 系统交互、社交网络 |
| 循环反馈 | 控制框图、反馈图 | 控制系统、闭环流程 |
| 发散结构 | 思维导图、概念图 | 主题展开、知识体系 |

---

## 判断决策树

```
输入：用户的自然语言描述或参考图片

第一步：是否有明确的时间/流程顺序？
├─ 是 → 进入流程图判断
│   └─ 流程图判断：
│       ├─ 有决策分支？ → 决策流程图
│       ├─ 有并行步骤？ → 并行流程图
│       ├─ 有循环回路？ → 循环流程图
│       └─ 线性步骤？ → 线性流程图/时序图
│
└─ 否 → 进入第二步

第二步：是否有明确的层级关系？
├─ 是 → 进入组织架构判断
│   └─ 组织架构判断：
│       ├─ 人员/部门关系？ → 组织架构图
│       ├─ 分类体系？ → 树图/分类图
│       └─ 功能分解？ → 层次结构图
│
└─ 否 → 进入第三步

第三步：是否有系统组件交互？
├─ 是 → 进入系统架构判断
│   └─ 系统架构判断：
│       ├─ 有数据流向？ → 数据流图
│       ├─ 有控制信号？ → 控制框图
│       ├─ 有模块依赖？ → 系统架构图
│       └─ 有网络拓扑？ → 网络拓扑图
│
└─ 否 → 进入第四步

第四步：是否有中心主题和分支？
├─ 是 → 思维导图/概念图
│
└─ 否 → 关系图/网络图
```

## 各类图表详解

### 1. 流程图 (Flowchart)

**特征：**
- 节点表示步骤、操作、决策
- 边表示流转方向、条件
- 有明确的起点和终点
- 可能包含分支、循环、并行结构

**适用场景：**
- 业务流程描述
- 操作步骤说明
- 决策逻辑展示
- 审批流程

**识别信号：**
- 关键词："步骤"、"流程"、"然后"、"接着"、"如果...那么"、"循环"
- 结构特征：线性推进 + 分支判断

**节点形状标准：**
- 椭圆：开始/结束
- 矩形：处理步骤
- 菱形：决策判断
- 平行四边形：输入/输出
- 圆角矩形：子流程

**示例描述：**
"用户登录后验证账号，如果验证通过进入主页，否则提示错误重新登录"

---

### 2. 组织架构图 (Organization Chart)

**特征：**
- 节点表示人员、部门、角色
- 边表示汇报关系、管理关系
- 明显的层级结构
- 树状或类树状布局

**适用场景：**
- 公司组织架构
- 部门结构
- 团队分工
- 权责体系

**识别信号：**
- 关键词："部门"、"团队"、"汇报"、"管理"、"负责"、"下属"
- 结构特征：明确的上下级关系

**布局特点：**
- 自上而下（rankdir=TB）
- 或自左向右（rankdir=LR）
- 同级节点对齐

**示例描述：**
"CEO下面有CTO和CFO，CTO管理技术部和产品部，CFO管理财务部和法务部"

---

### 3. 控制框图 (Control Flow Diagram)

**特征：**
- 节点表示系统组件、模块
- 边表示控制信号、数据流
- 可能包含反馈回路
- 强调输入-处理-输出关系

**适用场景：**
- 控制系统设计
- 反馈回路分析
- 系统模块关系
- 信号处理流程

**识别信号：**
- 关键词："系统"、"模块"、"输入"、"输出"、"反馈"、"控制"、"传感器"
- 结构特征：组件交互 + 反馈回路

**典型元素：**
- 输入源
- 处理单元
- 输出端
- 反馈路径
- 控制器

**示例描述：**
"温度传感器采集数据传给控制器，控制器处理后发送指令给执行器，执行结果反馈给传感器形成闭环"

---

### 4. 思维导图 (Mind Map)

**特征：**
- 中心主题节点
- 多层分支展开
- 发散状结构
- 强调层级和关联

**适用场景：**
- 主题展开
- 知识体系梳理
- 头脑风暴结果
- 分类归纳

**识别信号：**
- 关键词："主题"、"分支"、"包括"、"分为"、"方面"
- 结构特征：一个中心 + 多个分支

**布局特点：**
- 放射状布局
- 中心节点突出
- 分支向外扩展

**示例描述：**
"项目管理包括范围管理、时间管理、成本管理，时间管理又包括进度计划、进度控制"

---

### 5. 系统架构图 (System Architecture Diagram)

**特征：**
- 节点表示组件、服务、模块
- 边表示依赖、通信、数据流
- 可能有层级分组
- 强调系统整体结构

**适用场景：**
- 软件架构设计
- 系统集成方案
- 微服务架构
- 技术栈展示

**识别信号：**
- 关键词："系统"、"服务"、"模块"、"组件"、"接口"、"调用"、"依赖"
- 结构特征：多个组件 + 复杂交互

**典型分组：**
- 表现层
- 业务层
- 数据层
- 基础设施层

**示例描述：**
"前端应用调用API网关，网关路由到用户服务和订单服务，两个服务都访问MySQL数据库"

---

### 6. 时序图 (Sequence Diagram)

**特征：**
- 强调时间顺序
- 参与者沿垂直轴排列
- 消息沿水平方向传递
- 适合展示交互过程

**适用场景：**
- 系统交互流程
- API调用时序
- 协议通信过程
- 服务调用链

**识别信号：**
- 关键词："交互"、"调用"、"请求"、"响应"、"时序"、"消息"
- 结构特征：时间推进 + 消息交互

**典型元素：**
- 参与者（Actor）
- 生命线（Lifeline）
- 消息（Message）
- 激活框（Activation）

**示例描述：**
"用户向服务器发送登录请求，服务器查询数据库验证，返回token给用户"

---

### 7. 数据流图 (Data Flow Diagram)

**特征：**
- 节点表示处理过程、数据存储
- 边表示数据流向
- 强调数据的流动和变换
- 不关注控制逻辑

**适用场景：**
- 数据处理流程
- ETL流程
- 信息流向分析
- 数据仓库设计

**识别信号：**
- 关键词："数据"、"流向"、"输入"、"输出"、"存储"、"处理"
- 结构特征：数据移动路径

**典型符号：**
- 圆形：处理过程
- 开口矩形：数据存储
- 箭头：数据流
- 矩形：外部实体

**示例描述：**
"订单数据经过清洗、转换后存入数据仓库，供报表系统读取分析"

---

### 8. 网络拓扑图 (Network Topology)

**特征：**
- 节点表示网络设备
- 边表示连接关系
- 强调物理或逻辑布局
- 可能标注带宽、协议等信息

**适用场景：**
- 网络架构设计
- 基础设施规划
- 数据中心布局
- 设备连接关系

**识别信号：**
- 关键词："网络"、"服务器"、"路由器"、"交换机"、"连接"、"拓扑"
- 结构特征：设备节点 + 连接关系

**布局引擎选择：**
- 简单结构：dot
- 复杂网络：neato 或 fdp
- 大规模网络：sfdp

## 识别信号与关键词

### 综合关键词对照表

| 图表类型 | 核心关键词 | 结构信号 |
|---------|-----------|---------|
| 流程图 | 步骤、流程、然后、如果、循环 | 线性 + 分支 |
| 组织架构图 | 部门、汇报、管理、负责、下属 | 层级关系 |
| 控制框图 | 系统、模块、输入、输出、反馈 | 组件 + 回路 |
| 思维导图 | 主题、分支、包括、分为 | 中心 + 发散 |
| 系统架构图 | 服务、组件、接口、调用、依赖 | 组件 + 交互 |
| 时序图 | 交互、调用、请求、响应、时序 | 时间 + 消息 |
| 数据流图 | 数据、流向、输入、输出、存储 | 数据路径 |
| 网络拓扑图 | 网络、服务器、路由器、连接 | 设备 + 连接 |

## 选择建议

### 多图表适配场景

当内容可以适配多种图表类型时，参考以下优先级：

**场景1：业务流程描述**
- 优先：流程图（最直观）
- 备选：时序图（强调交互时序）

**场景2：组织关系描述**
- 优先：组织架构图（最经典）
- 备选：层级树图（更抽象）

**场景3：系统交互描述**
- 有反馈回路 → 控制框图
- 强调时序 → 时序图
- 强调架构 → 系统架构图

**场景4：知识体系描述**
- 主题展开 → 思维导图
- 分类体系 → 树图

### 混合结构处理

当内容包含多种结构特征时：

1. **识别主导结构**：判断哪种结构最核心
2. **拆分子图**：复杂结构可拆分为多个关联图表
3. **使用高级图表**：泳道图、复合架构图等

---

## 总结

图表类型选择的本质是**匹配内容结构与可视化形式**：

1. 理解内容：提取实体、关系、结构特征
2. 匹配类型：根据决策树选择最合适的图表类型
3. 优化表达：选择合适的布局引擎和样式模板

**核心原则：让图表服务于理解，而非为了可视化而可视化。**
