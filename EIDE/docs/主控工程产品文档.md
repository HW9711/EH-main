# 第1章 系统概述

## 1.1 产品定位

本产品为**骨科手术动力系统主控板**，型号 **F413EXOsSSCH_RTOSV1.5**，是骨科手术动力工具的核心控制单元。主控板负责管理多通道手柄、电机驱动、蠕动泵、脚踏输入、触摸屏人机交互以及与外部上位机的通信，同时提供完整的安全保护和控制仲裁机制，确保手术过程中设备的安全、可靠和精确运行。

主控板基于 **STM32F413VGT6** 微控制器，运行 **FreeRTOS v10.3.1** 实时操作系统，采用分层软件架构设计，具备多手柄热插拔识别、多路电机/泵并行控制、多输入源控制仲裁、看门狗保护和报警管理等功能。

## 1.2 主要功能概述

| 功能模块 | 说明 |
|---------|------|
| **多手柄管理** | 支持 A/B 两个通道手柄，每通道独立检测在线状态，支持6种手柄类型（TMBB/TMBA/EMBA/EMBB/PXBA/PXBB）。手柄插拔自动检测、去抖、CRC 认证、上线/离线事件驱动 |
| **电机控制** | 通过 UART 与电机驱动板通信，支持正转、反转和往复模式，支持多种刀具类型适配，实时速度/电流反馈与报警检测 |
| **蠕动泵控制** | A 泵和 B 泵独立控制，支持抽水、注水、灌注三种模式，流量0-70档位可调，内置压力闭环保护 |
| **脚踏/踏板输入** | 通过 UART4 接收脚踏板数据，支持单踏板和双踏板类型，内置定标校准机制，踏板值按比例控制电机速度并联动注水泵 |
| **触摸屏 UI** | 通过 USART3 与迪文串口屏通信，支持多页面切换，速度/频率/泵速/方向/刀具/报警等信息实时显示，屏幕按键通过行为队列统一派发 |
| **外部通信** | 通过 USART2 与外部上位机通信，支持外部控制申请/释放、静态值设置、EEPROM 读写、心跳上传、报警变化上报等功能 |
| **安全保护** | 独立看门狗（IWDG）防卡死；多级报警体系；控制仲裁防止多输入源冲突；外控链路超时保护 |

### 3.2.2 软任务调度器架构

系统使用**软任务调度器（Kernel Scheduler）**模式：

- 每个业务模块创建自己的 `kernel_task_t`（即 `task_t`）句柄
- 每个软任务通过 `task_t` 结构体管理，内含**独立的FreeRTOS线程**（静态TCB+栈）
- 每个软任务线程栈深度 **1024字**（StackType_t）
- 软任务通过**静态内存分配**，不消耗 FreeRTOS heap
- 支持两种运行模式：
  - `KERNEL_TASK_ALWAYS` (0x00)：周期运行
  - `KERNEL_TASK_ONE_SHOT` (0x01)：单次运行

### 3.2.3 task_t 结构体

```c
typedef struct task_s {
    uint32_t period;            // 周期(ms)
    uint32_t timerTick;         // 计时器
    bool oneShot;               // 单次模式标志
    bool start;                 // 启动标志
    bool threadCreated;         // 线程是否已创建
    const char *name;           // 任务名称
    TaskHandle_t threadHandle;  // FreeRTOS任务句柄
    StaticTask_t threadTcb;     // 静态TCB
    StackType_t threadStack[1024]; // 静态栈
    uintptr_t traceBeginHandle; // Tracealyzer事件句柄
    uintptr_t traceEndHandle;
    uintptr_t traceCreateHandle;
    uintptr_t traceStartHandle;
    uintptr_t traceStopHandle;
    uintptr_t traceOneShotStopHandle;
    cbFunc func;                // 业务回调函数
    struct task_s *next;        // 链表指针
} task_t;
```

### 3.2.4 软任务 API

| API | 说明 |
|-----|------|
| `Kernel_TaskCreate(task, func)` | 创建软任务（宏，自动填充函数名） |
| `Kernel_TaskCreateNamed(task, name, func)` | 创建软任务（指定名称） |
| `Kernel_TaskStart(task, one_shot, time_ms)` | 启动软任务 |
| `Kernel_TaskStop(task)` | 停止软任务 |
| `Kernel_QueueCreate(length, item_size, name)` | 创建队列 |

## 3.3 初始化流程

系统启动严格按以下顺序执行：

```
main()
  │
  ├─ 1. HAL_Init()                  // 复位外设, 初始化Flash和SysTick
  ├─ 2. SystemClock_Config()        // PLL: HSE 8MHz → 100MHz SYSCLK
  ├─ 3. MX_GPIO_Init()             // GPIO和EXTI初始化
  ├─ 4. MX_DMA_Init()              // DMA1和DMA2初始化
  ├─ 5. MX_USART1_Init() ~ MX_UART10_Init()  // 9路UART初始化
  ├─ 6. MX_TIM7/10/14_Init()       // 定时器初始化
  ├─ 7. Tracealyzer_RecorderInit() // Tracealyzer初始化
  ├─ 8. MX_I2C_Init()              // 初始化业务 I2C2/I2C3
  ├─ 9. App_Bootstrap()            // 应用引导:
  │     ├─ board初始化
  │     ├─ Kernel_Init()           // 内核调度器初始化
  │     ├─ 各模块Init依次调用（见下表）
  │     └─ Kernel_TaskStart()      // 启动所有软任务
  └─ 10. osKernelStart()           // 启动FreeRTOS调度器
```

# 第4章 手柄管理模块

## 4.1 手柄类型定义

### 4.1.1 手柄型号枚举

系统支持六种手柄类型，通过 EEPROM Page2 前两个字节（`0x6B xx`）识别：

| 代号 | EEPROM原始码 | 内部型号宏 | 值 | 说明 |
|------|-------------|-----------|-----|------|
| TMBB | `0x6B 0x01` | `TMBB_ONLINES` | 1 | 有线手柄 B 型 |
| TMBA | `0x6B 0x02` | `TMBA_ONLINES` | 2 | 有线手柄 A 型 |
| EMBA | `0x6B 0x03` | `EMBA_ONLINES` | 3 | 电动手柄 A 型 |
| EMBB | `0x6B 0x04` | `EMBB_ONLINES` | 4 | 电动手柄 B 型 |
| PXBA | `0x6B 0x05` | `PXBA_ONLINES` | 5 | 气动手柄 A 型 |
| PXBB | `0x6B 0x06` | `PXBB_ONLINES` | 6 | 气动手柄 B 型 |

> **设计要点**：外部通信心跳包上传的手柄类型使用 EEPROM Page2 原始两个字节，而不是 `handlescan.c` 内部映射后的单字节型号。

### 4.1.2 刀具型号枚举

系统支持六种刀具类型，通过 EEPROM Page3 前两个字节（`0x7C xx`）识别：

| 原始字节 | 内部型号宏 | 值 | 名称 | 说明 |
|---------|-----------|-----|------|------|
| `0x7C 0x01` | `MX_YIM_ONLINES` | 7 | MXYTM | 磨削 一体磨 |
| `0x7C 0x02` | `MX_YIP_ONLINES` | 8 | MXYTP | 磨削 一体刨 |
| `0x7C 0x03` | `PX_YIM_ONLINES` | 9 | PXYTM | 刨削 一体磨 |
| `0x7C 0x04` | `PX_YIP_ONLINES` | 10 | PXYTP | 刨削 一体刨 |
| `0x7C 0x05` | `JMB_ONLINES` | 11 | JMB | — |
| `0x7C 0x06` | `MX_YIM16_ONLINES` | 12 | MXYTM16 | — |

### 4.1.3 通信模式

- **有线手柄**：通过物理连接器接入，使用 GPIO 检测在线状态和按键输入
- **RFID 无线手柄**：通过 1-Wire 接口（DS2401）识别

## 4.2 双通道管理

系统支持 A/B 两个手柄通道，独立管理：

| 项目 | 通道A | 通道B |
|------|-------|-------|
| 通道标识 | `CHANNEL_A` (1) | `CHANNEL_B` (2) |
| 短接检测引脚 | PD1 (H_MD2) | PD0 (H_MD1) |
| 手柄数据引脚 | M_D1(PD2), M_D2(PD3), M_D3(PD4) | 共用 |
| 按键输入引脚 | H_MD3(PC12) | H_MD1(PD0), H_MD2(PD1) |
| 按键中断 | KEY0(PC10) | KEY1(PC11) |
| 1-Wire | 1-Wire I (PD13) | 1-Wire II (PD12) |

当前选中通道由全局变量 `channel_work` 控制。

## 4.3 手柄扫描状态机 (handlescan.c)

扫描周期由独立的 FreeRTOS 软任务驱动。

### 扫描流程

```
开始扫描
  │
  ├─ 1. 读取短接检测引脚 → 判断手柄是否物理连接
  │     ├─ 未连接 → 标记离线，通知ExternalComm（FunCode=0xCC）
  │     └─ 已连接 → 继续
  │
  ├─ 2. 读取 M_D 引脚组合 → 初步判断手柄类型
  │
  ├─ 3. 读取手柄 EEPROM (AT24CS32)
  │     ├─ CRC校验 → 失败则报警 WORK_ALARM_HANDLE_MODEL_ERROR_A/B
  │     └─ 成功 → 提取 Page2 手柄信息 + Page3 刀具信息 + Page4 初始值
  │
  ├─ 4. 映射内部型号 → 更新全局状态
  │
  └─ 5. 通知外部通信模块 → 发送接插切换事件（FunCode=0xCC）
```

## 4.4 手柄按键处理 (handlekey.c)

### 4.4.1 中断驱动的按键检测

- **KEY0 (PC10)** 和 **KEY1 (PC11)** 通过 EXTI 中断触发
- `HAL_GPIO_EXTI_Callback()` 在边沿触发时切换按键状态
- 防抖处理：按下 **15个周期** 确认，释放 **10个周期** 确认
- 扫描周期：**30ms**（HANDLEKEYTaskFunc）

### 4.4.2 按键功能

| 条件 | 按键行为 |
|------|----------|
| `channel_work==CHANNEL_A && hand_model==PXBA_ONLINES` | 通道A PXBA手柄按键扫描 |
| `channel_work==CHANNEL_B && hand_model==PXBB_ONLINES` | 通道B PXBB手柄按键扫描 |
| 已有报警 (alarm 11/12) | 阻止电机启动 |
| 脚踏模式 (JTWORK) | 阻止手柄启动，报警 `WORK_ALARM_FOOT_SELECTED` |
| 无冲突 | 切换电机启动/停止 |

### 4.4.3 控制仲裁

按键操作前必须获取控制权：
1. 检查 `ControlArbitration_IsBusyByOther(CONTROL_OWNER_HANDLE)`
2. 若空闲，申请 `CONTROL_OWNER_HANDLE` 控制权
3. 获取成功后才能操作电机/泵

## 4.5 控制仲裁机制 (ControlArbitration)

管理多输入源的互斥控制：

| 控制源 | 宏定义 | 值 |
|--------|--------|------|
| 无 | `CONTROL_OWNER_NONE` | 0 |
| 外部通信 | `CONTROL_OWNER_EXTERNAL` | 1 |
| 脚踏 | `CONTROL_OWNER_FOOT` | 2 |
| 屏幕 | `CONTROL_OWNER_SCREEN` | 3 |
| 手柄 | `CONTROL_OWNER_HANDLE` | 4 |

**仲裁规则**：同一时刻只有一个控制源可以操作电机/泵；控制源释放时（掉线、超时）自动释放控制权。

## 8.1 通信接口

| UART | USART2 |
| TX/RX | PD5 / PD6 |
| 波特率 | 9600 |

## 8.2 协议帧格式

```
┌──────┬─────────┬────────┬────────┬────────┬──────────┬────────┬─────────┬──────┐
│ 帧头 │ TranCode│ Length │ FunCode│AreaCode│ InforCode│InforArea│  CRC16  │ 帧尾 │
│ 4B   │   1B    │  2B    │  1B    │  1B    │   1B     │  N B   │   2B    │ 4B   │
└──────┴─────────┴────────┴────────┴────────┴──────────┴────────┴─────────┴──────┘
```

| 字段 | 字节数 | 值 | 说明 |
|------|--------|------|------|
| 帧头 | 4 | `0xD7 0xCA 0xF8 0xF1` | "梓锐" GBK编码 |
| TranCode | 1 | 0x01=上行, 0x02=下行 | 传输方向标识 |

| FunCode | 1 | — | 功能码 |
| AreaCode | 1 | — | 区域代码 |
| InforCode | 1 | — | 信息代码 |
| InforArea | N | — | 数据区（不定长） |
| CRC16 | 2 | — | CRC16校验（高字节在前） |
| 帧尾 | 4 | `0xBF 0xC6 0xBC 0xC4` | "科技" GBK编码 |

## 8.3 上行功能码（主机→上位机）

| FunCode | 功能 | 说明 |
|---------|------|------|
| 0x01 | EEPROM内容上传 | AreaCode指定区域，InforCode指定具体字段 |
| 0x02 | 设置内容上传 | 当前速度/方向/泵流量/频率/刀头模式 |
| 0x03 | 运行内容上传 | 实时速度/电流/泵压力/报警信息 |
| 0xAA | 心跳上传 | 手柄/泵/脚踏在线状态和运行参数（100ms周期） |
| 0xBB | 主动退出外部控制 | 通知上位机主机退出外部控制模式 |
| 0xCC | 接插切换通知 | 手柄/泵/脚踏接入/退出/切换事件 |
| 0xDD | 应答上传 | 设置/控制/权限的结果 |
| 0xEE | 控制命令回传 | 泵启停、手柄启停的控制确认 |

### 8.3.1 心跳包 (FunCode=0xAA)

心跳周期：**100ms**

InforArea 字段布局：
```
[A手柄在线] [A手柄类型(2B)] [B手柄在线] [B手柄类型(2B)]

在线状态码：在线 `0x01`，掉线 `0xFF`  
手柄运行状态：待机 `0x01`，运行中 `0x02`，未接入 `0x03`

## 8.5 外部通信任务 (external_comm_task.c)

外部通信任务运行在独立 FreeRTOS 线程中：

1. **UART2 DMA接收**：中断驱动，软件FIFO缓冲
2. **协议帧解析**：帧头/帧尾匹配，长度校验，CRC16校验
3. **命令分发**：根据FunCode分发到对应的处理函数
4. **响应生成**：构造应答帧并发送
5. **心跳机制**：100ms周期主动上报系统状态
6. **外部控制权限管理**：
   - 申请外部控制需8字节注册码验证
   - 链路保活：**1s**无心跳 → 停止电机/泵输出
   - 链路保活：**5s**无心跳 → 释放外部控制权限

### 8.5.1 外部控制申请流程

```
上位机发送 FunCode=0x01 + 8字节注册码
  │
  ├─ 主控板验证注册码
  │   ├─ 失败 → 应答 0xDD/0xBB (注册码校验失败)
  │   └─ 成功 → 申请 CONTROL_OWNER_EXTERNAL
  │       ├─ 被占用 → 应答 0xDD/0xAB (失败)
  │       └─ 空闲 → 应答 0xDD/0xAA (成功)
  │           └─ 进入外部控制模式
  │               ├─ 100ms心跳保活
  │               ├─ 1s超时 → 停止输出
  │               └─ 5s超时 → 释放权限，退出外部控制
